# ADR-002: Key-Safe Client-Side Encryption

## Status
Accepted (Resolved via R-C)

## Context
The seller needs to securely pass sensitive secrets (e.g., alarm PIN, key-safe code) to the buyer (F-8). These secrets must not be visible to anyone else, including the platform operators, and must be destroyed after expiry (F-10).

## Decision
We will implement client-side encryption for key-safe secrets. Secrets will be encrypted in the browser using a per-handover symmetric key before being sent to the server. The server will only store the ciphertext and a nonce.

## Rationale
- Zero-knowledge storage ensures that the platform cannot read the alarm codes.
- It fulfills the requirement N-2 (client-side encryption).
- The encryption key can be derived from the high-entropy handover token, meaning only participants with the token can decrypt the secrets.

## Consequences
- Secrets cannot be queried, filtered, or processed server-side.
- The UI must handle key derivation, encryption, and decryption locally.
- Loss of the handover token implies total loss of the secrets (which is acceptable and desired post-expiry).
