# ADR-004: Frontend Structure and TypeScript Conversion

## Status
Accepted (Resolved via E-2)

## Context
The initial prototype was a single 451-line `App.jsx` file. This is unmaintainable for the actual product development and lacks type safety.

## Decision
We will rewrite `App.jsx` in TypeScript (`App.tsx`) and decompose it into:
1. **Typed UI Components** (e.g., `Dashboard`, `ChatWindow`, `Header`, `Sidebar`, `Manuals`, `TechGuide`) located in `src/components/`.
2. **Pure Domain Modules** (e.g., tokens, expiry logic, masking rules) located in `src/lib/`.

## Rationale
- Componentization allows for parallel development and easier testing.
- Pure domain modules in `src/lib/` can be rigorously unit-tested with Vitest without mounting React components, ensuring 100% coverage on core logic (E-2).
- Strict TypeScript enforcement catches errors early and documents the data model expectations.

## Consequences
- All new code must be TypeScript.
- Any domain logic (date math, validation) must be extracted to `src/lib/`.
- UI components will be tested via RTL and Playwright.
