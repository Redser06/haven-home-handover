# ADR-001: Backend Platform Selection

## Status
Accepted (Resolved via R-A)

## Context
Haven requires auth (magic link), relational data, secure document storage, realtime chat, and row-level security. We need a backend to store and sync this securely. The initial prototype contained a vestigial Firebase config, but no concrete backend implementation.

## Decision
We will use Supabase for the backend platform, leveraging its Auth, Postgres database, Storage, and Realtime features. We will deploy the frontend via Lovable/Antigravity's auto-deploy options.

## Rationale
- Supabase provides a unified solution for Auth, Postgres, Storage, and Realtime.
- Row-Level Security (RLS) in Postgres maps perfectly to Haven's requirement: "a token grants access to exactly one handover". This guarantees cross-tenant isolation at the data layer (F-14).
- Magic link auth is supported out-of-the-box.
- It is well supported by the current stack and Lovable integrations.

## Consequences
- Vestigial Firebase configuration will be removed.
- All database interactions must be authenticated and subject to strict RLS policies.
- Development must include Supabase local/remote migrations and schemas.
